# SSCircle V10.49.1.8 | Mail Box + Auto Pairing release stabilization

## Why this hotfix exists
The V10.50 registration-status Mail Box PR changed the intended access model: an applicant with a valid `ssc_player` session can read their own pending/accepted/rejected messages. Two older gates still enforced accepted-only access. This broke GitHub Actions and blocked the Cloudflare ZIP artifact.

## Changes
- `/api/player/mailbox`: keep session and per-applicant ownership checks, allowing status notifications for pending/rejected.
- `/mailbox`: authenticated pending/rejected applicants can open the standalone Mail Box without entering the members-only Player Dashboard; accepted members continue to the Profile popup.
- `/mailbox.html`: canonical redirect to `/mailbox` for pending/rejected; anonymous requests still redirect to Cek Status.
- Activation request and secret reveal remain **accepted-only**, with server-side HTTP 403 checks. Sending a status notification does not activate a member.
- Both inbox clients start with activation disabled and fail closed if the response omits an explicit `applicationStatus`. Standalone Mail Box clears private messages and revealed codes when reload fails.
- Regression tests verify applicant access, secret denial, ownership isolation and redirect behavior.
- Paper `config.yml` comments now explain that a NEW server uses `server-pairing.properties` automatically after admin approval. Legacy `server-secret.txt` and environment secrets remain supported.

## Auto Server Pairing remains V10.49.1.7-compatible
No changes to HMAC algorithms, server IDs, approval codes or credential storage in this hotfix. New installations need the website URL and admin-approved `/sscircle pair` code. Do not upload the private pairing state file or legacy secrets.

## Deploy / rollback
1. Back up Cloudflare Pages deployment and D1 before release. Never overwrite secrets or production D1 data using a local backup.
2. Confirm GitHub Actions validation and all three Minecraft plugin builds are green.
3. Download the `SSCircle-Cloudflare-Upload` workflow artifact, extract its **inner Cloudflare ZIP** if GitHub provides a wrapper, then upload the site ZIP to the existing Cloudflare Pages project using Direct Upload. No destructive SQL or new D1 migration is required for this hotfix.
4. Verify `/api/health` returns `release: 10.49.1.8`, then test applicant statuses and accepted activation behavior. Preserve D1 and Cloudflare bindings such as `DB`, `SESSION_SECRET` and `ADMIN_PASSWORD`.
5. Keep Paper / SkinBridge V10.49.1.7 for this website-only compatibility hotfix. On a fresh server, check pairing state, admin approve, `/sscircle diagnose`, player linking, stats and skin. On old servers, retain the original secret; no forced re-pairing.
6. If runtime staging fails, rollback the Pages deployment only and restore the prior plugin JAR only if it was changed separately. Never delete D1, world, inventories, AuthMe records or pairing credentials to troubleshoot.

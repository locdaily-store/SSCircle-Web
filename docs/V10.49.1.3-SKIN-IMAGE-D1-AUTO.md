# SSCircle V10.49.1.3 · Skin PNG tersimpan di Cloudflare D1

## Kenapa status `SKIN_SUDAH_TERKIRIM` tetapi web kosong?

Pada V10.49.1.2, HTTP 200 hanya membuktikan **hash tekstur** tersimpan. Saat browser membuka foto, Worker harus mengunduh PNG dari `textures.minecraft.net`. Jika fetch tekstur gagal, gambar kosong walaupun hash sudah ada. Plugin juga menahan pengiriman ulang selama sesi bermain. V10.49.1.3 memperbaiki keduanya.

## Arsitektur V10.49.1.3

- SSCircleSkinBridge 10.49.1.3 membaca **sumber skin server**: SkinsRestorer 15.x (pilihan tersimpan/fallback) atau `PlayerProfile.getTextures()` Paper. Identitas selalu diambil dari SSCirclePlayerSync dan hasil autentikasi AuthMe/FastLoginPlus/Floodgate, **bukan nickname atau skin**.
- Plugin mengunduh PNG melalui URL **tetap** `https://textures.minecraft.net/texture/<hash>`, hanya menerima PNG Minecraft 64x32 atau 64x64 dan maksimal 128 KiB. Penarikan gambar dan upload dilakukan di Bukkit **async** dengan maksimal 2 pekerjaan bersamaan, timeout, dan retry bertahap sesudah login.
- Request ke Cloudflare memakai HMAC SHA-256, timestamp, nonce sekali pakai, batas ukuran, kepemilikan akun tertaut. Worker menulis metadata di `minecraft_account_skins` dan PNG base64 di `minecraft_account_skin_images`. PNG langsung disajikan dari D1 tanpa fetch keluar. Setiap record gambar berforeign key `ON DELETE CASCADE` ke akun tertaut.
- Website memeriksa akun tertaut tiap **20 detik** saat Profile terlihat **hanya jika ada akun yang belum menyimpan gambar PNG**. Avatar dan kartu diperbarui saat tersedia; tidak perlu refresh manual atau meminta OP menjalankan perintah setiap login.
- Premium yang telah terverifikasi masih mendapat fallback Mojang **khusus kosmetik** bila tidak ada PNG dari server. Non-Premium **tidak** di-resolve lewat nickname. Tidak ada perubahan ke linking, UUID, inventory, world, statistik, ataupun identitas.

## Pemasangan tahap demi tahap

1. **Backup** D1, secret dan `config.yml` di `plugins/SSCirclePlayerSync`, plugin AuthMe/FastLoginPlus/SkinsRestorer, dan world/playerdata. Jangan pernah mengunggah file secret ke chat atau GitHub.
2. Deploy **`SSCircle-Cloudflare-Upload-V10.49.1.3.zip`** ke Cloudflare Pages (ujikan di staging terlebih dahulu). Pastikan binding D1 bernama **`DB`** tetap mengarah ke database SSCircle yang berisi `minecraft_accounts`/`submissions`, dan secret **`SSCIRCLE_LINK_SERVER_SECRET`** sudah ada. **Tidak perlu database atau secret baru.**
3. Periksa `https://sscircle.pages.dev/api/health`: nilai release harus **`10.49.1.3`**. Jika memakai domain lain, cek domain yang dibuka pemain.
4. D1: otomatis dibuatkan tabel `minecraft_account_skin_images` oleh Worker saat endpoint dipanggil. Buka **Cloudflare Dashboard → Workers & Pages → D1 → database SSCircle → Console** dan jalankan `SELECT COUNT(*) AS total_images FROM minecraft_account_skin_images;`. Jika tabel belum ada, pastikan Worker V10.49.1.3 sudah dideploy dan binding `DB` benar. Bila perlu jalankan **hanya setelah backup di staging** isi `migrations/v10_49_1_3_skin_images.sql`. Jangan hapus tabel lain.
5. Stop Paper. **Pertahankan** SSCircle Player Sync 10.49.1 dan folder konfigurasi privatnya. Hapus **JAR addon SSCircleSkinBridge lama saja** (10.49.1.1 / 10.49.1.2). Pasang `SSCircle-Skin-Bridge-Paper-10.49.1.3.jar`. Hanya boleh ada satu versi addon. Pastikan SkinsRestorer kompatibel jika Non-Premium memakai skin custom.
6. Restart penuh. Sebagai OP jalankan `/ssskin status`: pastikan Core=YA, HTTPS=TERSEDIA, secret=TERSEDIA, dan **Tujuan upload skin** mengarah ke domain yang sama dengan website Profile. Contoh `https://sscircle.pages.dev/api/minecraft/skin/sync`, tanpa `.html` pada endpoint core.
7. Pemain masuk ke server. Selesaikan AuthMe dan pastikan akun Minecraft sudah ditautkan. Plugin mencoba sendiri setelah join, dengan retry jika bukti autentikasi/skin belum siap atau akun baru selesai di-link. Tidak perlu mengetik `/sscircle sync` atau `/ssskin sync` untuk login harian.
8. Untuk diagnosis OP jalankan `/ssskin inspect NAMA_MINECRAFT` setelah beberapa saat. Hasil **`SKIN_GAMBAR_TERSIMPAN_HTTP_200`** berarti Worker mengakui **PNG di D1**, bukan hanya hash. Buka Profile dan tunggu pengecekan otomatis. Jika masih kosong, klik **Periksa skin lagi** atau lakukan hard refresh `Ctrl+Shift+R`.

## Diagnosis singkat

| `/ssskin inspect` | Arti / perbaikan |
| --- | --- |
| `SKIN_GAMBAR_TERSIMPAN_HTTP_200` | PNG berhasil diterima dan tersimpan di D1; bila tidak tampak, periksa status endpoint dan sesi Profile |
| `SKIN_GAMBAR_SUDAH_TERSIMPAN_DI_D1` | Addon memiliki konfirmasi terakhir; untuk paksa verifikasi ulang jalankan `/ssskin sync NAMA` |
| `HASH_SAJA_HTTP_200_PNG_GAGAL_DIUNDUH` | Paper tidak dapat mengunduh PNG dari Mojang. Periksa DNS/firewall/akses textures.minecraft.net dari hosting |
| `WORKER_BELUM_SUPPORT_SIMPAN_PNG` | Cloudflare masih memakai Worker lama, atau respons upload tidak mengonfirmasi `imageStored:true`. Deploy ZIP 10.49.1.3 dan cek health |
| `LOGIN_BELUM_TERVERIFIKASI` | Selesaikan autentikasi AuthMe; addon mencoba ulang otomatis |
| `SKINSRESTORER_BELUM_MEMILIKI_SKIN` / `PAPER_TIDAK_MEMILIKI_TEKSTUR` | Tidak ada tekstur server terdeteksi. Periksa /skin dan API SkinsRestorer |
| `HTTP_404_SKIN_NOT_LINKED` | Akun belum dikonfirmasi/terhubung di D1 tujuan, atau endpoint server berbeda dengan web. Jangan reset akun |
| `HTTP_401_SKIN_SIGNATURE_INVALID` | Secret Worker dan plugin tidak sama. Koreksi tanpa membagikan nilainya |
| `HTTP_503_SERVER_SECRET_MISSING` | Secret Cloudflare belum diatur |
| `HTTP_500` | Periksa log Worker; pastikan binding D1 dan tabel ada |

## Opsional: pemeriksaan di browser

Buka Profile SSCircle dengan sesi Dashboard aktif. Klik **Lihat skin 3D → Periksa skin lagi**. Pada Developer Tools → Network, periksa request `/api/player/minecraft/skin/ACCOUNT_ID`:

- **200** `Content-Type: image/png` dan `X-SSC-Skin-Source: server-d1` berarti gambar dibaca dari D1.
- **404** berarti belum ada skin server yang tersimpan pada akun tersebut.
- **403** berarti sesi Dashboard perlu autentikasi lagi.
- **503** berarti referensi lama masih butuh fetch eksternal; jika addon baru berhasil, referensi lama akan diganti oleh PNG di D1.

Jangan menyalin screenshot yang memperlihatkan cookies, Authorization header, kode pendaftaran, token, atau secret.

## Pengujian dan batasan

- Node.js test mencakup upload HMAC, PNG valid/invalid, privasi akun, D1, endpoint metadata, browser viewer, serta regresi fitur SSCircle lama.
- Addon telah **dikompilasi lokal dengan stub Bukkit** sehingga sintaks Java teruji, **belum diuji sebagai plugin yang benar-benar berjalan pada Paper 26.3/Java 25 maupun SkinsRestorer pengguna**. Build Gradle resmi memakai Paper API harus dilakukan di CI/staging sebelum production.
- Uji di staging, jangan mengganggu server utama dan jangan menghapus D1/AuthMe lama.

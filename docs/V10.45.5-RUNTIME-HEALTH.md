# SSCircle V10.45.5 — Pemeriksaan layanan produksi

Tujuan: membantu pengurus mencari alasan **Profile** dan **Admin Control** tidak terbuka walaupun secret dan binding terlihat pada Cloudflare Dashboard. Perbaikan ini **tidak** mengganti database, password, atau nilai secret. Tidak ada fallback yang mengabaikan keamanan.

## Pemeriksaan pertama setelah deploy

1. Unduh `SSCircle-Cloudflare-Upload.zip` dari GitHub Actions versi V10.45.5 dan deploy ke **Production** pada proyek Pages yang melayani domain `sscircle.pages.dev`. Upload ZIP bagian dalam artifact, bukan ZIP pembungkus.
2. Buka `https://sscircle.pages.dev/api/health`.
3. Periksa field `release`. **Harus `10.45.5`**. Jika route tidak ditemukan/versi lain muncul, URL ini belum menjalankan deploy yang tepat.
4. Periksa `checks` dan `services` (tidak ada secret, data akun, atau baris database dalam respons).
5. Saat sudah `profile: ready`, buka Profile melalui Cek Status dengan login anggota **Diterima**. Jika belum login, pengalihan ke halaman Cek Status adalah perilaku yang benar.

## Interpretasi checks

| Field | Nilai | Penyebab kemungkinan |
| --- | --- | --- |
| `data` | `binding-missing` | Worker deploy ini tidak menerima binding database |
| `data` | `query-failed` | Binding ada namun kueri tes dasar gagal |
| `data` | `schema-missing` | Database yang terhubung tidak berisi tabel `submissions`; kemungkinan proyek/database staging atau kosong |
| `data` | `ready` | Binding berhasil mengakses database dengan skema inti |
| `playerSession` | `unavailable` | Worker tidak menerima secret sesi dalam deployment saat ini |
| `adminLogin` | `unavailable` | Worker tidak menerima secret password admin |
| `minecraftLink` | `unavailable` | Kunci penghubung Minecraft belum tersedia / tidak valid |

Kode bantuan: `SSC-D01` masalah koneksi data; `SSC-S01` secret sesi; `SSC-A01` password admin; `SSC-M01` kunci Minecraft; `SSC-OK` konfigurasi pokok terlihat siap.

## Bila binding/secret sudah terlihat di Dashboard tetapi checks belum ready

- Pastikan kamu membuka proyek Pages yang **tepat** untuk domain `sscircle.pages.dev`, bukan Workers project lain atau proyek Pages dengan nama mirip.
- Pastikan setiap binding dan secret disetel pada lingkungan **Production** (bukan hanya **Preview**).
- Pastikan nama binding D1 adalah `DB`, mengarah ke **database lama SSCircle yang berisi data**, bukan database baru/kosong.
- Pastikan secret `SESSION_SECRET` dan `ADMIN_PASSWORD` ada dan tidak kosong di Production.
- Deploy ulang **setelah** binding/secret disimpan. Cloudflare menyuntikkan binding/secret ke deployment yang relevan; keberadaannya di UI pengaturan saja tidak membuktikan worker aktif sudah menerimanya.
- Jangan mengganti `SESSION_SECRET` yang lama tanpa rencana migrasi: sesi login dan akses pesan terenkripsi bisa terganggu.
- Jangan mengirim isi secret/password ke chat, GitHub issue, log publik, atau screenshot.

## Perlindungan

Profile tetap menolak akses jika sesi tidak valid atau pendaftar belum berstatus Diterima. Bila binding hilang, halaman gangguan berdesain SSCircle menggantikan halaman teks hitam dan menampilkan kode bantuan aman. Admin Control menampilkan kode bantuan bila backend belum tersambung; password yang salah tetap ditolak. Endpoint `/api/health` **hanya mengembalikan status dan kode diagnosis**, bukan nilai secret, nama database, IP, isi akun, atau SQL internal. Kueri cek database bersifat baca-saja dan tidak mengubah data.

Jika `/api/health` menyatakan semua `ready` tetapi akses tetap gagal, periksa HTTP status / path pada browser Network dan Cloudflare real-time logs (tanpa menampilkan token).

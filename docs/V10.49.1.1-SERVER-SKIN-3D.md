# SSCircle V10.49.1.1: Server Skin Sync & 3D Viewer

## Penyebab gambar/tombol tidak muncul pada V10.49.1

Kode V10.49.1 hanya memperbolehkan skin `java_premium` yang diambil langsung dari Mojang. Pada offline-mode, plugin utama mengirim identitas AuthMe (`java_offline`), bukan UUID Mojang, sehingga avatar tidak berubah, permintaan skin ditolak, dan tombol `Lihat skin` disembunyikan. Selain itu plugin Paper sebelumnya sama sekali belum mengirim data skin aktif server. Inilah akar masalahnya, bukan sekadar CSS.

## Perubahan

1. **Plugin tambahan SSCircle Skin Bridge 10.49.1.1.** Bekerja bersama SSCircle Player Sync 10.49.1 Paper, tanpa mengganti file JAR lama. Core SSCircle tetap sumber otoritatif identitas terautentikasi, termasuk AuthMe/FastLoginPlus/Floodgate, melalui adapter refleksi khusus versi 10.49.1. Adapter menolak sesi yang belum lolos verifikasi login core.
2. **Sumber skin:** pertama coba SkinRestorer **v15.x** jika tersedia dan aktif; bila gagal gunakan tekstur di `PlayerProfile` Paper. Skin yang hanya dikirim melalui packet/mod tanpa penyimpanan server mungkin tidak terbaca; aplikasi tidak berpura-pura berhasil.
3. **Sinkronisasi skin:** setiap login, tiap 300 detik (disebar di beberapa tick), atau lewat OP `/ssskin sync`. Pembacaan identitas/profile Bukkit di main thread, pembacaan API SkinsRestorer di thread async, HTTPS async dan maksimum dua pencarian bersamaan. Tidak membaca statistik Vanilla dan tidak mengganti inventory/world.
4. **Worker:** endpoint baru `POST /api/minecraft/skin/sync` memverifikasi HMAC, timestamp ±90 detik, UUID nonce sekali pakai, status keanggotaan, identitas provider+ID yang sudah tertaut dan waktu verifikasi awal. Di D1 dibuat tabel aditif `minecraft_account_skins` (account_id, texture_hash, model, source, updated_at), sehingga data lama tetap utuh. Hanya hash tekstur dari `textures.minecraft.net` yang diperbolehkan, tanpa URL bebas, tanpa menyimpan PNG/base64 atau secret di D1.
5. **Profile:** avatar kepala mengikuti skin akun utama jika tersedia, termasuk akun offline atau Bedrock (jika data skin sah terbaca oleh server). Tiap akun mempunyai tombol `Lihat skin` yang tetap terlihat, dan modal 3D CSS3D lokal (tanpa CDN) dengan rotasi drag, roda mouse zoom, tombol putar/reset, dukungan keyboard, serta overlay layer skin dan tipe classic/slim. Saat skin belum tersinkron tampil pesan yang benar, bukan gambar/identitas palsu.
6. **Cache:** file JS/CSS diberi versi baru untuk mencegah browser menyajikan script lama.

## Paket

- `SSCircle-Cloudflare-Upload-V10.49.1.1.zip` untuk Cloudflare Pages **Direct Upload**; file `index.html`, `_worker.js`, `_routes.json` berada di root.
- `SSCircle-Skin-Bridge-Paper-10.49.1.1.jar` addon Paper (jangan mengganti/menamai ulang core SSCirclePlayerSync).
- Core lama `SSCircle-Player-Sync-Paper-10.49.1.jar` milik pengguna tetap digunakan. Tidak ada file D1 backup atau secrets yang disertakan.
- ZIP source seluruh proyek berisi source addon dan tes regresi untuk kolaborasi/build resmi di CI.

## Instalasi STAGING sebelum Production

1. Backup Cloudflare D1, folder private `plugins/SSCirclePlayerSync/` (terutama `server-secret.txt`, `stats-queue.properties`), AuthMe, FastLoginPlus, world/playerdata, dan SkinRestorer (jika ada). Tidak ada kebutuhan reset/migrasi data.
2. Upload ZIP website ke Cloudflare Pages staging **yang sudah punya D1 binding dan secrets sama dengan plugin**. Periksa `GET /api/health`: `release = 10.49.1.1`. Tabel baru akan dibuat saat API Member Center dipakai. Bila error SQL, periksa binding, jangan reset D1.
3. Simpan **dua JAR terpisah** di `plugins/`: core `SSCircle-Player-Sync-Paper-10.49.1.jar` dan addon `SSCircle-Skin-Bridge-Paper-10.49.1.1.jar`. Hindari lebih dari satu versi core. Bila memakai SkinRestorer, pasang versi yang kompatibel dengan Paper 26.3. Stop/start Paper penuh (bukan `/reload`).
4. Di konsol/OP game jalankan `/ssskin status`: harus menunjukkan core aktif, endpoint+secret tersedia. Jika core config sebelumnya belum lengkap, perbaiki `plugins/SSCirclePlayerSync/config.yml` dan `server-secret.txt`, kemudian `/ssskin reload`.
5. Login Minecraft dengan akun yang sudah ditautkan ke Profile SSCircle. Tunggu proses join dan skin diterapkan oleh SkinRestorer; OP jalankan `/ssskin sync`. Jika akun baru, konfirmasi linking di Profile terlebih dahulu sebelum sinkronisasi ulang.
6. Login **Profile SSCircle** memakai password dashboard. Buka **Akun Minecraft Saya**, lihat avatar setiap kartu dan tekan **Lihat skin**. Jika akun terhubung namun gambar tidak tampil, cek adanya skin plugin, `/ssskin status`, akses `textures.minecraft.net` dari Cloudflare, dan permintaan `/api/player/minecraft/skin/<accountId>` di Network browser.
7. Setelah semua checklist staging lolos, baru deploy production menggunakan backup baru. Tidak otomatis merge repo GitHub atau deploy hosting.

## Checklist

- [ ] `/api/health` menampilkan release 10.49.1.1, DB siap dan tidak ada error 500.
- [ ] `/ssskin status` menunjukkan core, endpoint HTTPS dan secret tersedia (nilainya tetap rahasia).
- [ ] Java Non-Premium terautentikasi dengan AuthMe dan SkinRestorer memakai skin yang terlihat di server; skin tersebut tampil di Profile setelah `/ssskin sync`.
- [ ] Java Premium dengan UUID Mojang terverifikasi tetap bisa memakai skin, tanpa mengubah edisi login.
- [ ] Bedrock Floodgate menggunakan XUID terautentikasi; jika skin tidak tersedia bagi plugin, fallback ditampilkan jelas, bukan skin pemain Java lain.
- [ ] Skin akun A dan B tersimpan terpisah, memilih akun utama mengubah avatar Profile tanpa memindahkan statistik/inventory.
- [ ] Popup 3D menampilkan lapisan luar, bisa diputar/zoom/reset melalui mouse, touch, dan keyboard; resolusi HP tidak overflow.
- [ ] HMAC salah, nonce ulang, akun yang belum tertaut, akun milik member lain, hash selain texture host resmi ditolak oleh Worker.
- [ ] Koneksi Mojang/textures terputus atau gagal tidak merusak Profile dan login; tidak ada error/lag di Paper.
- [ ] Cek TPS/MSPT dengan Spark, jangan klaim bebas lag sebelum menguji hosting nyata.

## Hal yang belum diuji

Build addon dikompilasi terhadap **stub minimal API Bukkit dengan Java 21**, bukan build Gradle terhadap Paper API 26.3. Kelas Java 21 compatible dengan runtime Java 25, tetapi kompatibilitas runtime Paper 26.3, autentikasi campuran, SkinsRestorer v15.x dan Cloudflare production masih perlu pengujian nyata. Browser 3D diuji dengan skin contoh sintetis, bukan player asli. Tanpa SkinsRestorer atau sumber skin di PlayerProfile, fitur tidak bisa menebak skin custom client-only.

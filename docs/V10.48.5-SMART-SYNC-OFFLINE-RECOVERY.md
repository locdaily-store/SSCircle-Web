# SSCircle V10.48.5 — Smart Sync, Offline Recovery & TPS protection

## Ruang lingkup dan baseline

Berbasis `main` commit `90b615607f97786112aec75bb1bf5d93b6d4b0c3`
(V10.48.4.3). Tidak memigrasi D1, mengganti UUID, mengubah autentikasi
AuthMe/FastLoginPlus, menghapus kode linking, ataupun mengubah payload API.

### 1. Smart Sync statistik yang menyesuaikan TPS

- Snapshot Vanilla tetap dibaca pada **main thread Paper** melalui
  `getStatistic`, dalam batas jumlah material yang dibaca per tick.
- Secara default maksimal **24 pembacaan material/tick**. Ketika sampel
  TPS Paper satu menit di bawah **18.0**, jumlah maksimal menjadi **6/tick**.
- Pembacaan sampel TPS dilakukan sekitar **sekali per detik**, bukan
  pada tiap material. Jika Paper tidak menyediakan sampel, plugin
  tidak mengarang nilai TPS dan memakai budget normal.
- Mode adaptif pemain sibuk dan interval snapshot yang ada tetap
  berlaku. Tidak melakukan HTTP maupun penulisan antrean pada main thread.

Pengaturan baru pada `plugins/SSCirclePlayerSync/config.yml`:

```yaml
stats-sync:
  tps-aware-enabled: true
  low-tps-threshold: 18.0
  low-tps-block-reads-per-tick: 6
```

Jika file config lama tidak memiliki opsi ini, kode memakai default di atas.
Saat mengatur nilai terlalu ekstrem, implementasi membatasi budget aman.

### 2. Offline Recovery dan anti-spam Cloudflare

- Queue statistik lama tetap di `stats-queue.properties` dan dipulihkan
  pada restart bersama baseline snapshot terakhir, bukan hanya data pending.
- Pemulihan baseline mencegah sampel keluar cepat yang tidak lengkap
  membuat blok mined tampak nol. Data tetap dikirim memakai eventId dan
  kontrak pengiriman sebelumnya.
- Statistik dan pembaruan bukti login memakai *exponential backoff*
  maksimal **300 detik**, tambahan jitter kecil, dan menghormati
  header `Retry-After` (HTTP 429 atau 503, detik atau tanggal RFC 1123).
  Retry tetap asinkron, sehingga Cloudflare yang gangguan tidak
  menghasilkan HTTP berulang setiap tick.
- Backoff bukti login disimpan per **sesi UUID yang divalidasi**, bukan
  berdasarkan nickname. Join sesi baru membuat state baru.
- Respons sukses mereset backoff; HTTP 401/403 tidak pernah dipaksa sukses.
- `/sscircle sync` tetap mengantrekan tangkapan statistik dan
  pembaruan bukti. Bila server sedang membatasi pengiriman karena error,
  perintah tersebut tidak melewati `Retry-After`.

### 3. Batas keamanan dan kompatibilitas

- HMAC SHA-256, nonce, expiry, endpoint HTTPS, pemeriksaan AuthMe,
  interpretasi sesi FastLoginPlus, dan kepemilikan akun **tidak diubah**.
- `CRACKED` atau `OFFLINE` tetap **bukan bukti tidak memiliki lisensi**.
  Hanya bukti FastLoginPlus `PREMIUM` sah atau Paper online-mode yang
  boleh memberi status Premium terverifikasi.
- Antrean lokal bersifat privat. Jangan upload `server-secret.txt`,
  `stats-queue.properties`, atau database AuthMe ke GitHub.
- Queue yang tidak valid tidak dikirim ke backend. Admin perlu melihat
  log dan backup sebelum menyentuh file antrean.

## Deployment ke staging, lalu produksi

1. Backup D1 Cloudflare, konfigurasi, `server-secret.txt`, antrean
   `stats-queue.properties`, database AuthMe/FastLoginPlus, world dan
   `playerdata`; jangan reset atau pindahkan UUID.
2. Unduh **dua artefak dari run commit yang sama** di GitHub Actions:
   JAR Paper `10.48.5` dan paket upload Cloudflare `10.48.5`.
3. Deploy Cloudflare lebih dulu ke staging/Pages yang terikat D1 dan
   secret lama. Pastikan `/api/health` menampilkan rilis `10.48.5`.
4. Hentikan Paper, sisakan **satu** JAR SSCircle saja, ganti versi lama,
   pertahankan `plugins/SSCirclePlayerSync/`, kemudian restart.
   Server Paper tetap `26.3` / Java `25`.
5. Jalankan `/sscircle status` **di chat pemain** untuk bukti autentikasi,
   `/sscircle diagnose` bagi OP, dan `/sscircle sync` untuk memicu
   snapshot. Pantau Admin Control → Minecraft Sync dan log Paper.
6. Uji sementara: matikan akses HTTPS **di staging**, tetap bermain,
   restart Paper dengan antrean tertunda, pulihkan koneksi, dan pastikan
   statistik terkirim tanpa hilang, tanpa duplikasi angka, dan tidak
   menyebabkan lag. Jangan sengaja memutus jaringan produksi.
7. Uji 20–50 pemain dengan profiler Spark atau pembacaan MSPT/TPS asli.
   Angka performa **tidak diklaim** sampai uji server nyata selesai.
8. Uji Java Premium resmi, Java offline + AuthMe, dan Bedrock (jika aktif).
   `getStatus(UUID)==CRACKED` memerlukan diagnosis autentikasi dari
   FastLoginPlus/ProtocolLib/launcher, **bukan perubahan label**.

## Verifikasi kode

JUnit meliputi backoff, batas, `Retry-After`, dan serialisasi snapshot;
Node regression meliputi kontrak Paper dan health Worker. GitHub Actions
membangun paket untuk pemeriksaan kompatibilitas. Hasil CI tidak
menggantikan uji staging server dengan kombinasi plugin sebenarnya.

# SSCircle V10.51.0 - Member Directory & Friend Requests

## Features
- Members with active password Dashboard sessions can search other accepted members by opt-in display name or linked Minecraft username (minimum two characters).
- Search returns only members whose profile visibility permits member discovery. Private members are not discoverable; existing friends may still see each other's profile until friendship is removed. Dashboard login by registration code alone does not grant social access.
- Selected member profile shows bio if admin permits, verified linked Minecraft account names, server-supplied skin 3D viewer, playtime/deaths/kills/blocks statistics when enabled by the owner and admin, and published Season awards.
- No registration tracking codes, password or security metadata are returned by social APIs.
- Request, accept, decline, cancel, and remove friendships. Pending and accepted states are persisted in additive D1 tables `member_friendships` and `member_social_notices`.
- The recipient receives a private Mail Box request. The recipient can accept or decline directly from that notification. The sender receives a response notification.
- Friend request actions require an authenticated member's strong Dashboard session; requests are limited to 15 actions per 15 minutes and declined requests cannot be re-sent for seven days.
- The trusted backend verifies each profile and skin image request; a social skin may only be loaded from verified server-supplied D1 PNG, without guessing or impersonating Minecraft identities.

## Setup
1. Back up the production Cloudflare D1 database and previous Pages deployment.
2. Verify all GitHub Actions tests pass; use the Cloudflare ZIP artifact from the same commit.
3. Upload `SSCircle-Cloudflare-Upload.zip` to the existing Cloudflare Pages project and retain bindings `DB`, `SESSION_SECRET`, and `ADMIN_PASSWORD`. The new tables are created additively.
4. In Player Dashboard, activate and log in with the password using Mail Box activation. Set Profile visibility to **Member** (or Public if admin allows) and enable **Tampilkan statistik** if you want other members to see them.
5. Open **Cari Member & Teman**, find an opt-in member and choose **Tambah teman**. The recipient opens Mail Box and presses **Terima pertemanan** or **Tolak**.
6. Confirm Profile's skin 3D button uses the skin already provided by SSCircle Player Sync / Skin Bridge. Neither Minecraft plugin needs changes in this release.

## Test checklist
- [ ] Anonymous/registration-code-only sessions cannot search, invite, or read private social skins
- [ ] Pending/rejected registration cannot access social features
- [ ] Private members do not appear in search; opted-in members do
- [ ] Stats hidden when the owner/admin disables sharing
- [ ] Friend request appears in recipient's Mail Box and cannot be accepted by the sender
- [ ] Acceptance results in mutual friendship, Mail Box reply, and appropriate profile access
- [ ] Decline blocks immediate repeat requests for seven days
- [ ] Removing friendship restores privacy for formerly private profiles
- [ ] Incorrect/unknown social skin IDs and direct URL attempts are denied
- [ ] 3D viewer and mobile UI render, without horizontal overflow
- [ ] Cloudflare Pages and D1 staging and Paper 26.3 are checked on real devices

## Rollback
Rollback the Cloudflare Pages deployment without deleting the additive tables, existing D1 data, the Minecraft server's world or its private server pairing credentials. This release does not require a new Paper/Velocity/SkinBridge JAR.

## Limitations
These features expose opt-in member fields only. All-Time statistics and Season records are shown only if already synchronized and attributed to a verified Minecraft account; missing statistics are never fabricated. A completed CI workflow is not a substitute for a live end-to-end Cloudflare D1 and Minecraft server test.

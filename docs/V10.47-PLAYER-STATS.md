# SSCircle V10.47.0 — Player Statistics Sync

## Status dan cakupan
- **Sudah diimplementasikan dalam source:** sinkronisasi statistik dari Paper ke Cloudflare D1, snapshot dan antrean lokal, tampilan Profile, jalur HTTP HMAC, perlindungan replay/duplikasi, dan perintah pengurus.
- **Wajib diverifikasi di staging:** perilaku nyata Paper 26.3 + AuthMe/PacketEvents dan/atau Geyser/Floodgate; koneksi Cloudflare produksi, data statistik di dunia nyata, dan waktu respon saat 20–50 pemain online.
- **Belum termasuk:** reset season, statistik pemain offline yang belum tertaut, leaderboard otomatis, dan migrasi world UUID/playerdata.

## Statistik yang dikirim
| Nama | Sumber di Paper | Tampilan Profile |
| --- | --- | --- |
| Playtime | `Statistic.PLAY_ONE_MINUTE` (tick vanilla dibagi 20) | Jam + menit |
| Deaths | `Statistic.DEATHS` | Jumlah kematian |
| Mob kills | `Statistic.MOB_KILLS` | Jumlah mob dikalahkan |
| Blocks mined | Total `Statistic.MINE_BLOCK` untuk blok-blok yang valid | Jumlah blok ditambang |

Tombol/layar Profile tidak menambahkan statistik manual dan tidak menampilkan nol jika belum ada snapshot server. Jumlah season tetap `Belum tersedia` hingga integrasi season diselesaikan. Statistik kumulatif `MAX` mencegah snapshot lebih tua atau retry menurunkan angka. Konsekuensinya, reset world/new season belum otomatis memulai angka baru; perlu sumber/epoch season khusus.

## Alur keamanan dan sinkronisasi

1. Server Paper membaca statistik vanilla untuk pemain **yang berhasil melewati verifikasi identitas SSCircle**; pemain Java belum login AuthMe dan identitas Floodgate tidak valid dilewati.
2. Snapshot disimpan privat di `plugins/SSCirclePlayerSync/stats-queue.properties`; antrean mencatat **satu snapshot terbaru per identitas** (maksimum 1024 identitas). Ditulis dengan file sementara dan pemindahan atomik bila filesystem mendukung.
3. Secara default, sampel diambil saat pemain bergabung (setelah waktu autentikasi), setiap **300 detik**, saat keluar, dan ketika plugin berhenti. Pengurus dapat mengetik `/sscircle sync` untuk memaksa pengambilan statistik yang siap diverifikasi.
4. Plugin mengirim request `POST /api/minecraft/stats/ingest` via HTTPS dan signature HMAC-SHA256 yang sama dengan sistem linking; setiap request memiliki timestamp dan nonce unik. **Secret tidak dicatat dalam chat/log**.
5. Backend Cloudflare hanya menerima UUID Mojang melalui `mojang-online`, akun Java AuthMe terverifikasi melalui `authme-session`, atau XUID Floodgate melalui `floodgate-xuid`. Klaim dari browser tanpa signature ditolak.
6. Backend memastikan identitas sudah **tertaut dan dikonfirmasi** dalam `minecraft_accounts`, dan anggota berstatus Diterima. Snapshot yang dibuat sebelum pemilik akun tersebut melakukan linking tidak boleh berpindah ke pemilik baru.
7. D1 menyimpan event idempotensi di `minecraft_stat_receipts` dan angka kumulatif dalam `player_stat_snapshots` melalui batch transaksional, tidak menggandakan angka pada retry.
8. Jika HTTP gagal, antrean tetap di disk dan dicoba ulang dengan penundaan bertingkat maksimum 5 menit. Jika identitas belum tertaut, snapshot tersebut dibuang (pengukuran berikutnya akan tercatat setelah linking); tidak menyimpan log kode yang sensitif.

## Instalasi
1. **Backup D1, seluruh folder `plugins`, `world`, `world/playerdata`**. Jangan pindah online-mode atau UUID sebagai bagian dari pembaruan statistik.
2. Perbarui Cloudflare Pages ke ZIP **V10.47.0** dan pertahankan binding `DB`, `SESSION_SECRET`, serta `SSCIRCLE_LINK_SERVER_SECRET` lama. D1 menambah tabel penerimaan `minecraft_stat_receipts` secara aditif; tabel akun dan snapshot yang sudah ada tetap dipakai.
3. Matikan Paper. Ganti hanya JAR SSCircle lama di `plugins` dengan `SSCircle-Player-Sync-Paper-10.47.0.jar`; **jangan hapus** `plugins/SSCirclePlayerSync/server-secret.txt`, `config.yml`, atau `stats-queue.properties`.
4. Tambahkan konfigurasi di `plugins/SSCirclePlayerSync/config.yml` jika sebelumnya belum ada:

   ```yaml
   stats-sync:
     enabled: true
     interval-seconds: 300
   ```

   Pertahankan `endpoint`, `authme-mixed-mode`, dan konfigurasi yang sebelumnya berhasil.
5. Nyalakan Paper. Jalankan `/sscircle diagnose`, `/sscircle status` dan `/sscircle sync` sebagai OP. Pemain mesti sudah terhubung ke Profile website.
6. Refresh `/my-sscircle`. Empat statistik muncul sesudah snapshot pertama diterima. Teks `Sinkron terakhir` menunjukkan waktu sampel aktual.

## Label Jenis Minecraft
- `java_premium` → **Premium**
- `java_offline` (akun AuthMe) → **Non-Premium**
- `bedrock` → **Minecraft Bedrock**

Catatan: pada server AuthMe mixed-mode, pemain Java yang memakai Premium Bypass juga saat ini dicatat sebagai `java_offline` karena API publik AuthMe belum menyediakan bukti Mojang per sesi. Akibatnya label `Non-Premium` merepresentasikan *kelas link AuthMe*, bukan vonis status lisensi Minecraft pemain. Pemisahan Premium dengan bukti kriptografis tetap target pengembangan.

## Diagnostik
| Kasus | Perilaku |
| --- | --- |
| Website offline / HTTP 5xx / 401 | Data tetap berada di antrean, dicoba kembali dengan backoff |
| Website belum memiliki endpoint statistik | Tetap retry HTTP 404 tanpa `STATS_NOT_LINKED`; deploy ZIP terbaru |
| Akun belum ditautkan | Snapshot tak dikaitkan dengan akun website, sampel berikutnya dicoba |
| Statistik lama tiba setelah snapshot baru | Angka tidak diturunkan |
| Pemain belum login AuthMe | Statistik tidak diklaim atas identitas tersebut |
| Bedrock XUID tidak tersedia | Sinkronisasi diblokir, bukan dianggap Java Premium |
| File antrean gagal disimpan | Pengurus diberi peringatan privat pada log server |

## Tahap lanjutan
- **V10.47.1:** tes end-to-end 3 jenis pemain, disconnect/reconnect, simulasi Cloudflare gagal, statistik setelah unlink dan relink, durasi snapshot, dan performa untuk 20–50 pemain.
- **V10.47.2:** perbaikan berdasarkan log uji nyata; metrik antrean/backoff, batasan storage, laporan error lebih jelas.
- **V10.48:** Admin Control pemantauan statistik/health per akun dan kontrol status Player Sync.
- **V10.49:** multi-account linking, identitas Premium mixed-mode yang benar-benar terverifikasi, skin dan profil pemain.
- **V10.50+:** sinkronisasi season (epoch/reset yang jelas), leaderboard otomatis, Hall of Fame, statistik bangunan dan event.

Perubahan D1 ini **tidak** menghapus tabel lama, tidak membagikan secret, dan tidak membuat sesi pemain tanpa login. Pengujian CI membuktikan kode dapat dibangun, bukan bukti sukses pada infrastruktur produksi.

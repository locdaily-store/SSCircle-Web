# SSCircle V10.48.4.3 — Hasil audit `latest(6).log` dan monitoring HTTP 400

## Temuan terverifikasi dari log server (10 November 2026)
- Paper 26.3 build 214, Java 25; server menjalankan `online-mode=false`
  dan listener internal menerima player hanya pada alamat `127.0.0.1:25565`.
- AuthMe 6.0.1-b2770, FastLoginPlus 1.0.0-27aa0db,
  ProtocolLib 5.4.0, PacketEvents 2.14.0, Geyser/Floodgate dan
  SSCircle V10.48.4.2 semuanya dimuat.
- FastLoginPlus terhubung dengan AuthMe, mengaktifkan listener
  konfigurasi Paper, serta mengambil alih verifikasi Premium AuthMe.
- Paper tetap melaporkan
  `HorriblePlayerLoginEventHack: PlayerLoginEvent ... [ProtocolLib]`.
  Ini bisa menonaktifkan **reconfiguration APIs** yang penting
  bagi alur autentikasi. Proses integrasi FastLoginPlus bisa
  terpengaruh, tetapi log **belum membuktikan** ini penyebab tunggal
  sesi Premium bertanda OFFLINE.
- Log menampilkan UUID pemain berbentuk UUID versi 3 (kemungkinan
  offline-mode UUID). Jangan menyimpulkan lisensi hanya dari UUID.
  `premiumUuid: true` pada FLP tidak membuat autentikasi otomatis
  sukses dan tidak boleh diubah tanpa rencana migrasi playerdata.
- SSCircle mengirim `IDENTITY_SYNC_OK` tetapi ini hanya berarti
  website menerima bukti sesi, **bukan Premium berhasil diverifikasi**.
- `Monitoring: Laporan ditolak (HTTP 400)` memiliki bug konkret
  di Worker: regex nomor versi heartbeat hanya menerima
  `10.A.B`, menolak `10.48.4.2`.

## Perbaikan V10.48.4.3 yang diimplementasikan
1. **Worker:** menerima versi telemetry `10.x.y` dan `10.x.y.z`
   (hanya digit, pembatas 1–3 digit), menolak versi yang
   terlalu panjang atau berisi karakter berbahaya.
2. **Tes endpoint:** menyimulasikan heartbeat HMAC untuk
   `10.48.4.2` dan `10.48.4.3`; memverifikasi bahwa format salah
   tetap HTTP 400.
3. **Plugin `/sscircle status` (OP):** menampilkan daftar plugin
   yang mendaftarkan `PlayerLoginEvent`, sehingga warning Paper
   dapat didiagnosis dari perintah tanpa mengekstrak log 100+ baris.
   Output hanya menyebut nama plugin, tidak mencetak IP,
   username, UUID, token, dan password.
4. **Konteks console:** sekarang menjelaskan bahwa console
   tidak mempunyai sesi pemain; pengecekan Premium harus
   dijalankan dari dalam Minecraft.
5. **PaperSyncTelemetry:** membedakan error heartbeat 400,
   kesalahan secret/jam (401/403), dan endpoint Worker lama (404).
   HTTP tetap asynchronous; tidak menambah blocking ke server tick.

## server.properties untuk campuran Java Premium / Non-Premium dan Bedrock

Jika server **langsung Paper**, tanpa Velocity/Bungee, dengan
AuthMe+FastLoginPlus dan Geyser/Floodgate:

```properties
online-mode=false
enforce-secure-profile=false
```

- Pertahankan `authme-mixed-mode.enabled: true` pada SSCircle
  jika konfigurasi mode campuran dan autentikasi AuthMe sudah aman.
- `server-ip=127.0.0.1` hanya dapat menerima koneksi dari
  komputer itu sendiri; untuk hosting yang harus dapat diakses
  dari luar gunakan bind yang sesuai dengan arsitektur jaringan
  (`server-ip=` untuk semua interface) **dengan firewall,
  AuthMe, rate-limit, dan perlindungan akses**. Jangan asal
  membuka backend langsung bila menggunakan reverse proxy.
- Pada **server hanya Java Premium**, barulah `online-mode=true`
  mungkin tepat; itu akan menolak Java Non-Premium.
- Untuk jaringan Velocity, konfigurasi forwarding dan online
  mode **berbeda**; jangan gunakan petunjuk standalone ini.

## Investigasi Premium yang aman (staging dahulu)

1. Backup database AuthMe dan FastLoginPlus, world/playerdata, folder
   SSCircle, D1 serta konfigurasi ProtocolLib.
2. Pakai launcher Minecraft resmi yang sedang login ke akun Microsoft
   yang berhak memakai Java Edition. Reconnect dan jalankan
   `/sscircle status` **dalam permainan**, bukan dari console.
3. Bila hasil `PREMIUM`, periksa pengiriman bukti ke Cloudflare;
   plugin SSCircle tidak boleh mengubah statusnya secara paksa.
4. Bila hasil `OFFLINE`, lihat warning Paper tentang ProtocolLib,
   dan bandingkan log FastLoginPlus ketika player login.
   Periksa versi ProtocolLib yang memang kompatibel dengan Paper 26.3;
   pada log versi 5.4.0 memperingatkan belum diuji.
   **Jangan mencabut ProtocolLib langsung dari produksi**
   karena FastLoginPlus standalone memerlukannya.
5. Pada staging yang dibackup, uji pembaruan ProtocolLib/
   FastLoginPlus yang kompatibel serta kemungkinan listener
   `PlayerLoginEvent` versi lebih baru. Aktifkan `debug: true`
   di FastLoginPlus **hanya selama tes**, hapus/anonimkan IP
   dan token dari log sebelum membagikannya, lalu matikan kembali.
6. Jangan memindahkan UUID, mengganti `premiumUuid`,
   menggunakan `/flp premium` tanpa verifikasi kepemilikan,
   atau menghapus registrasi AuthMe untuk mempercantik label.
7. Periksa `/sscircle status` untuk monitoring HTTP 400 dan
   `/sscircle diagnose` setelah memasang **JAR dan Worker
   V10.48.4.3 bersama-sama**.

## Temuan tambahan bukan penyebab utama
- GeoIP AuthMe tidak berhasil mengunduh database MaxMind sehingga
  proteksi GeoIP tidak aktif, bukan kegagalan verifikasi Mojang.
- AuthMe mengeluh tidak ada permission system; untuk server publik,
  pasang sistem permission yang cocok bila dibutuhkan.
- Paper menyebut build yang dipakai tertinggal, tetapi jangan
  memperbarui tanpa uji kompatibilitas LocLive, Geyser dan plugin lain.
- Link code `/sscircle link SC-...` tercatat pada log command server.
  Kode berumur singkat, namun sebaiknya diperlakukan sensitif dan
  disunting sebelum log dibagikan secara publik.

## Batas pengujian
CI membuktikan build dan kontrak endpoint benar. CI **bukan** tes
kepemilikan lisensi Microsoft atau login Mojang sungguhan.
SSCircle tidak dapat memperbaiki sendiri autentikasi FastLoginPlus
yang gagal pada layer ProtocolLib/Paper tanpa memperbaiki
dependency atau konfigurasi server.

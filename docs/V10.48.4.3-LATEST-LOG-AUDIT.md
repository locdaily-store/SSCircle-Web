# SSCircle V10.48.4.3 — Audit latest(6).log, mode server dan heartbeat

## Server properties untuk satu Paper (tanpa Velocity)

Untuk server **Java Premium + Java Non-Premium + Bedrock**:
```properties
online-mode=false
server-port=25565
# Gunakan 127.0.0.1 hanya untuk pengujian di komputer yang sama.
# Untuk hosting publik tanpa proxy, biarkan server-ip kosong.
server-ip=127.0.0.1
```

**Tidak perlu mengubah online-mode menjadi true** untuk sekadar menampilkan
Java Premium di SSCircle. `online-mode=true` menolak klien Java Non-Premium
pada server direct. Offline-mode membutuhkan AuthMe, FastLoginPlus dan
perlindungan keamanan yang benar, karena identitas tidak diperiksa oleh Paper.

Jangan ubah `premiumUuid`, `online-mode`, database AuthMe, playerdata,
inventory atau UUID pada server yang sudah memiliki pemain tanpa backup dan
prosedur migrasi.

## Fakta dari latest(6).log (10 November 2026, jam server 06:02-06:16)

- Paper 26.3 (build 214), Java 25, Windows; FastLoginPlus
  `1.0.0-27aa0db`, AuthMe `6.0.1-b2770`, ProtocolLib `5.4.0`,
  PacketEvents `2.14.0`, SSCircle `10.48.4.2` aktif.
- Paper secara eksplisit melaporkan `offline/insecure mode`; server
  bind pada `127.0.0.1:25565` (lokal).
- FastLoginPlus menemukan AuthMe, memakai direct connections, meregister
  Paper configure listener dan mengambil alih verifikasi packet Premium.
- UUID pemain Java yang terlihat adalah UUID version 3 yang konsisten
  dengan offline UUID. Ini petunjuk bahwa sesi tersebut tidak memperoleh
  Mojang UUID yang diverifikasi; bukan pembuktian tentang kepemilikan akun.
- Log memperlihatkan
  `HorriblePlayerLoginEventHack` menyebut `ProtocolLib`. Paper
  mengatakan listener `PlayerLoginEvent` legacy menonaktifkan
  reconfiguration APIs. Ini kompatibilitas yang perlu diuji bersama
  ProtocolLib/FastLoginPlus, **belum dapat ditetapkan sebagai penyebab tunggal**.
- SSCircle: `IDENTITY_SYNC_OK` dan statistik bisa terkirim, tetapi
  `Monitoring: Laporan ditolak (HTTP 400)`.
- Output status yang tercetak lengkap di log adalah hasil dari console.
  Console bukan `Player`, sehingga bagian `AKUN & BUKTI LOGIN` memang
  tidak ditampilkan. Untuk status per pemain, jalankan
  `/sscircle status` di **chat pemain dalam game**.
- Peringatan AuthMe GeoIP/MaxMind tidak menyebabkan error klasifikasi Premium.
- Log tidak mencatat keputusan/pesan alasan autentikasi Premium FLP per sesi.
  Perlu `plugins/FastLoginPlus/config.yml`: aktifkan `debug: true`
  **sementara**, restart, login sekali dari launcher resmi, ambil cuplikan
  yang relevan. Setelahnya kembalikan `debug: false`; jangan bagikan IP,
  kode linking, password, maupun secret plugin.

## Temuan bug yang sudah diperbaiki

Backend Cloudflare masih menerima `pluginVersion` heartbeat dengan pola
`10.x.y`, tetapi JAR mengirim `10.48.4.2`. Kondisi ini selalu
menghasilkan `TELEMETRY_INVALID` / HTTP 400 untuk rilis empat bagian.

V10.48.4.3 mengizinkan format `10.x.y` **atau** `10.x.y.z`, tanpa
melonggarkan HMAC, nonce, batas ukuran payload, maupun field lainnya.
Tes baru membuktikan versi `10.48.4.2` dan `10.48.4.3` diterima,
format rusak tetap ditolak, dan secret salah tetap ditolak.

Plugin juga menampilkan pesan monitoring yang lebih spesifik ketika
backend menolak data, peringatan untuk listener `PlayerLoginEvent`
ProtocolLib (hanya ketika terdeteksi), serta petunjuk bahwa console
tidak dapat menampilkan bukti login pemain.

**Tidak ada migrasi D1 baru, reset data, atau perubahan metode verifikasi
Premium.** Status FastLoginPlus `CRACKED` tidak boleh dipaksa menjadi
`PREMIUM`; selesaikan terlebih dahulu sumber masalah autentikasinya.

## Uji di staging setelah memasang

1. Backup folder `plugins/SSCirclePlayerSync` termasuk
   `server-secret.txt` dan antrean statistik, konfigurasi dan database
   AuthMe/FastLoginPlus, D1 dan `world/playerdata`.
2. Deploy ZIP Cloudflare **V10.48.4.3** dengan binding dan secret lama;
   jangan mengganti `SSCIRCLE_LINK_SERVER_SECRET`.
3. Hentikan Paper; ganti satu JAR SSCircle dengan **V10.48.4.3**;
   restart. Jangan menggunakan dua JAR SSCircle sekaligus.
4. Login dengan akun original melalui launcher resmi yang aktif.
   Jalankan **/sscircle status dari chat pemain**, bukan console.
   Jika `OFFLINE`, periksa log FastLoginPlus debug dan isu ProtocolLib.
5. Sebagai OP jalankan `/sscircle sync`, lalu cek status.
   Pada `Monitoring`, heartbeat berikutnya seharusnya diterima.
   Buka Admin Control → Minecraft Sync untuk memastikan heartbeat terbaru.
6. Jika host masih menunjukkan HTTP 400, cek deployment Cloudflare
   dan versi runtime di `/api/health`, bukan reset database.
7. Untuk menguji kompatibilitas ProtocolLib, gunakan backup di
   staging dan build yang secara eksplisit mendukung Paper 26.3.
   FastLoginPlus mensyaratkan ProtocolLib, sehingga **jangan asal
   menghapusnya pada produksi**.

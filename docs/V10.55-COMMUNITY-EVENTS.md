# V10.55.3 • Community Events, Achievements & 3-token voting

Website Cloudflare Pages Advanced Mode + D1. **Plugin SSCircle Player Sync 10.54.6 dan Skin Bridge 10.49.1.4 tidak berubah.**

## Event komunitas
- Member berstatus **Diterima** yang sudah membuka Profile menggunakan sesi password dashboard dapat mengajukan event melalui \`events.html\`.
- Lima pertanyaan: nama pelaksana/staff; judul; teknis; tanggal dan jam mulai; daftar hadiah Juara 1 sampai maksimal 20.
- Pengajuan tersimpan di D1 berstatus \`pending\`, **tidak diterbitkan otomatis**; maksimum tiga pengajuan pending per akun.
- Admin Control → Event & Jadwal memuat daftar pengajuan, kuota, tombol Setujui/Tolak, serta alasan penolakan.
- Event yang disetujui ditambahkan ke kalender publik tanpa menimpa \`eventsItems\` milik Admin Control. Acara yang sudah dibuat Admin tetap berlaku.
- Anggota Diterima dapat mendaftar satu kali pada event sebelum dimulai; kuota pendaftaran dijaga oleh perintah SQL atomik.
- Admin dapat memeriksa peserta dan menandai kehadiran, kemudian menetapkan Juara 1 dan seterusnya. Pemenang harus peserta yang sudah check-in.
- Penghargaan event disimpan satu kali berdasarkan event, anggota, dan nomor juara; badge terkait masuk ke sistem badge komunitas lama.
- Durasi pengajuan member bawaan dua jam. Admin menentukan kuota saat menyetujui. Sistem saat ini belum menyediakan waiting list, self-check-in otomatis, pembatalan peserta, atau validasi Minecraft langsung. Jangan menganggap fitur tersebut selesai.

## Achievements
- Aturan achievement disimpan dalam tabel D1 terpisah dan dapat diatur pada panel Event & Jadwal Admin Control.
- Metrik yang didukung: playtime (detik), mob kills, deaths, blocks mined, event attended.
- Contoh awal: Dedicated Player 100 jam, Monster Hunter 1.000 mob, Event Explorer 3 check-in.
- Achievement dievaluasi saat anggota membuka halaman Profile, tanpa polling plugin Paper, dan penyimpanan claim bersifat idempoten.
- Metrik statistik menggunakan nilai agregat tertinggi per akun website dari \`player_stat_snapshots\`, bukan menjumlah ulang musim sehingga tidak menggandakan progres. Audit season lanjutan tetap disarankan.

## Voting tiga token
- Satu anggota berstatus Diterima mendapat maksimum **tiga token per pertanyaan, per sesi voting**.
- Setiap token memilih **opsi berbeda**. Pilihan yang pernah digunakan tidak bisa dipilih lagi walaupun browser dimodifikasi.
- Validasi server dan update D1 atomik memeriksa sesi, status Diterima, maksimum tiga suara, dan larangan memilih opsi yang sama.
- Voting aktif baru membutuhkan setidaknya tiga pilihan per pertanyaan. Data suara sesi sebelumnya dipertahankan dan dapat memakai sisa token; reset sesi di Admin Control tetap tersedia.
- Pengaturan hasil polling lama tetap berlaku. Batas penyimpanan keseluruhan 5.000 suara masih ada; kapasitas di atas batas perlu migrasi ke tabel ballot tersendiri.

## Deploy Cloudflare
1. Buat backup D1 dan konfigurasi Cloudflare produksi.
2. Ambil artefak ZIP Cloudflare dari workflow \`Periksa dan kemas SSCircle untuk Cloudflare\` untuk commit V10.55.3 yang lulus semua pengujian.
3. Upload ZIP sebagai Cloudflare Pages **Direct Upload**. Pertahankan binding DB, MEDIA (bila dipakai) dan semua secret lama.
4. Tabel D1 tambahan dibuat otomatis secara idempoten ketika endpoint event pertama diakses. Tidak ada reset D1.
5. Masuk sebagai member diterima dengan sesi password Dashboard; ajukan event berisi lima isian.
6. Masuk Admin Control → Event & Jadwal, review dan setujui. Periksa kalender publik, pendaftaran peserta, check-in, penghargaan, achievement Profile.
7. Buat satu pertanyaan Voting dengan minimal tiga jawaban, pilih jawaban pertama, kedua, ketiga, dan pastikan duplikat/keempat ditolak.
8. Pastikan event tertolak tidak muncul di kalender, akun pending/rejected tidak dapat submit, dan event dengan kuota penuh tidak menerima peserta baru.

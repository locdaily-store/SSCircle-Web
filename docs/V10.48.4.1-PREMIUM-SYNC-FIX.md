# SSCircle V10.48.4.1 — Perbaikan tampilan Java Premium/Non-Premium

## Penyebab yang ditemukan di V10.48.4

- Label website berasal dari `minecraft_identity_evidence.auth_source` di D1.
  Pada versi lama, bukti sesi yang sudah lama masih bisa menyebabkan profil
  menunjukkan **Non-Premium** walaupun pemain sudah masuk kembali.
- Bukti `fastlogin-premium`, `fastlogin-cracked`, atau `authme-session` baru
  terutama dikirim bersama antrean statistik. Login yang tidak menghasilkan
  perubahan statistik bisa menunda pembaruan label pada website.
- Versi sebelumnya belum mempunyai request bukti sesi tersendiri. Sinkron
  statistik tidak boleh dimanipulasi hanya untuk menyegarkan label.

## Apa yang diperbaiki

1. **PaperIdentitySync** mengirim bukti sesi terkini lewat request HTTPS
   `POST /api/minecraft/identity/refresh`, terpisah dari statistik.
   Request dikirim asinkron, dilindungi HMAC-SHA256, nonce, timestamp,
   dan dibatasi maksimal tiga request bersamaan serta empat per putaran.
2. Setelah pemain masuk dan AuthMe menyatakan login sah, SSCircle membaca
   status sesi langsung dari FastLogin/FastLoginPlus:
   - `PREMIUM` → `fastlogin-premium`
   - `CRACKED` → `fastlogin-cracked`
   - `UNKNOWN` atau adapter tidak siap → `authme-session`
   Ini adalah **status sesi**, bukan status lisensi akun dari nama pemain.
3. Backend menerima pembaruan **hanya untuk akun yang telah ditautkan dan
   dikonfirmasi** oleh member SSCircle aktif. Bukti lama, spoofed, nonce
   duplikat dan bukti sebelum linking ditolak/diabaikan.
4. Website tidak lagi mengklaim **Non-Premium** atau **Premium** dari bukti
   login Java offline-mode yang lebih lama dari tujuh hari. Akun tetap
   tertaut dengan label **Premium belum terverifikasi**.
5. `/sscircle status` memperlihatkan hasil `getStatus(UUID)` langsung
   dari FastLoginPlus dan hasil pengiriman bukti ke Cloudflare. Perintah
   OP `/sscircle sync` juga memicu penyegaran bukti tanpa mengubah statistik.

Tidak ada migrasi tabel D1 baru, reset akun, reset statistik, pergantian
UUID, atau penggantian key. Kontrak stats dan konfirmasi linking tetap sama.

## Cara memasang

1. Buat backup server, `world/playerdata`, data AuthMe dan FastLoginPlus,
   `plugins/SSCirclePlayerSync/server-secret.txt`, `config.yml`,
   `stats-queue.properties`, serta snapshot D1 produksi.
2. **Deploy ZIP Cloudflare V10.48.4.1** ke project Cloudflare Pages yang
   digunakan website SSCircle. Pastikan binding `DB`, `SESSION_SECRET`
   dan `SSCIRCLE_LINK_SERVER_SECRET` tetap terpasang. Jangan gunakan
   GitHub Pages sebagai backend database dinamis.
3. Hentikan Paper, **ganti** JAR SSCircle lama dengan
   `SSCircle-Player-Sync-Paper-10.48.4.1.jar`, dan restart server.
   Jangan memasang dua JAR SSCircle sekaligus.
4. Pastikan versi di `/sscircle status` adalah `10.48.4.1`. Pastikan
   FastLoginPlus dan ProtocolLib benar-benar aktif, bersama AuthMe/
   PacketEvents pada mode campuran. Hanya satu FastLogin atau FastLoginPlus.
5. Login ulang menggunakan **launcher original** dengan autentikasi
   Microsoft/Mojang yang berhasil. Di dalam game jalankan
   `/sscircle status` dan periksa **Status sesi FastLoginPlus langsung**.
6. Jika status **PREMIUM**: setelah proses pembaruan identitas diterima,
   refresh halaman Profile. Jika status website masih lama, OP boleh
   menjalankan `/sscircle sync` untuk pemicu ulang; lihat baris
   **Pengiriman bukti ke web**.
7. Jika status **CRACKED**: FastLoginPlus memang melaporkan sesi itu sebagai
   login offline. SSCircle **tidak boleh** menyebutnya Premium berdasarkan
   username atau kepemilikan akun yang belum terbukti dari sesi tersebut.
   Periksa konfigurasi dan log FastLoginPlus, versi ProtocolLib, status
   login Microsoft launcher, konfigurasi proxy, dan konflik autentikasi
   AuthMe. Backup sebelum mencoba mengubah `premiumUuid`.
8. Jika status **UNKNOWN**: tunggu sesi adapter siap, periksa apakah
   FastLoginPlus benar-benar terpasang di backend Paper dan bukan hanya
   proxy; status yang tidak terverifikasi tidak boleh dianggap cracked.

### Peringatan
Perintah `/flp premium` atau `/premium` bukan bukti mandiri bahwa
handshake sesi Premium telah lolos. Jangan mengubah label menggunakan
nama pemain, UUID offline, data di browser, atau query SQL manual.

## Verifikasi dan tes otomatis

- Signed refresh: bukti palsu dan replay ditolak, unlinked/pending ditolak,
  bukti yang lebih lama tidak mengalahkan bukti terbaru.
- Data statistik dan tautan lama tidak berubah saat memperbarui bukti.
- Bukti Non-Premium kedaluwarsa tampil sebagai belum terverifikasi.
- Build plugin Java 25 Paper 26.3, pengecekan source dan website dilakukan
  melalui GitHub Actions.
- **Tes hosting nyata tetap diperlukan** untuk Java Premium, Java
  Non-Premium, Bedrock, FastLoginPlus dan variasi AuthMe.

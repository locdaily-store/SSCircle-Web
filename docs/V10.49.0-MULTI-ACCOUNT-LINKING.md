# SSCircle V10.49.0 — Multi-Account Linking & Per-Account Season Stats

## Ringkasan rilis
Website/Cloudflare Worker **10.49.0**, plugin **SSCircle Player Sync Paper 10.48.5** tetap kompatibel **tanpa perubahan JAR**. Jalur autentikasi, kode HMAC, nonce, secret dan `/sscircle link` tidak berubah. Tidak perlu Velocity.

Fitur:
1. Satu member SSCircle (status **Diterima**, sesi Dashboard dengan password) dapat menautkan sampai **3 akun Minecraft** (admin bisa mengatur 1–5).
2. Akun utama dan akun tambahan; akun utama menentukan identitas default di Profile, **tidak** memindahkan UUID/inventory/playerdata/izin server.
3. Setiap akun ditautkan dengan kode sekali-pakai 10 menit, verifikasi sesi nyata oleh Paper/AuthMe/FastLoginPlus/Floodgate, dan konfirmasi di browser. Satu identitas Minecraft tak bisa dimiliki dua member sekaligus.
4. Putuskan **satu tautan tertentu** dengan autentikasi ulang password Dashboard. Jika akun utama dilepas, akun tersisa menjadi utama. Tidak menghapus world, AuthMe atau statistik historis.
5. **Statistik Permainan**: pilih **akun Minecraft** dan **Season**. Opsi Gabungan Semua Akun tersedia. Data ditulis per `application_id + provider + provider_id + season_id` dan ringkasan anggota dihitung dari jumlah masing-masing akun.
6. Admin Control → Minecraft Sync: toggle penambahan akun, batas 1–5, dan delapan riwayat perubahan tertaut terbaru. Pengurangan batas tidak menghapus tautan yang sudah ada.

## Batasan keamanan
- Mode campuran Paper `online-mode=false` wajib memakai AuthMe dan FastLoginPlus sesuai konfigurasi SSCircle. `Premium=1` dalam database FastLoginPlus **bukan** bukti sesi Premium; label Premium hanya diberikan bila FastLoginPlus mengembalikan sesi `PREMIUM`.
- Java AuthMe offline membuktikan sesi akun lokal, bukan kepemilikan lisensi Mojang. Bedrock memakai XUID Floodgate yang sah.
- Nama pemain atau UUID offline tidak boleh menjadi otorisasi pengambilalihan identitas.
- Kode link/claim tidak boleh digunakan ulang; kedua sisi memerlukan sesi yang benar. Perubahan utama hanya untuk member, bukan perintah jarak jauh ke Paper.
- Tautan yang sudah dipakai anggota lain tidak otomatis ditransfer, bahkan sesudah kode link baru dikirim.
- Tabel audit mencatat member, akun internal, jenis tindakan dan waktu. Password, kode, IP maupun secret **tidak** dimasukkan ke audit.

## Cara statistik lama dipertahankan
- Pada akses pertama Worker V10.49.0, D1 membuat tabel aditif lalu **satu kali** memigrasikan progres dari `minecraft_stat_progress` ketika tepat satu akun sedang tertaut dan `provider/provider_id` cocok.
- Jika riwayat agregat lama tidak bisa dikaitkan secara aman dengan akun tertentu, disimpan sebagai **legacy residual** `minecraft_stat_legacy`. Angka ini termasuk total gabungan, tidak secara palsu diklaim milik salah satu akun; Profile memberi metadata `historicalUnassigned`.
- Akun baru menyimpan snapshot awal lifetime seperti perilaku V10.47; season baru tetap mulai dari baseline nol. Jika terdapat riwayat statistik akun yang pernah dimiliki member SSCircle lain, akun pemilik baru menggunakan baseline nol agar tidak mewarisi angka lama.
- Statistik tiap akun disimpan menurut identitas yang ditandatangani server. Sebelum menerima data, Worker memeriksa tautan aktif, waktu capture setelah verifikasi tautan, status member, HMAC, nonce, dan receipt.
- Pada pemutusan tautan, total historis tidak otomatis dihapus. Filter akun aktif tidak menampilkan akun yang sudah dilepas; log audit tetap ada.
- Statistik lintas akun adalah jumlah statistik yang sudah tercatat. Tidak ada penggabungan playerdata atau pengukuran TPS per permintaan.

## Pemasangan yang disarankan
1. **Backup penuh**: database D1 produksi, `plugins/SSCirclePlayerSync/` termasuk `server-secret.txt` dan `stats-queue.properties`, database AuthMe dan FastLoginPlus, `world/playerdata`, stats, permission, dan konfigurasi Geyser/Floodgate.
2. Gunakan **staging** Cloudflare Pages dengan D1 staging yang terpisah; jangan mengeksekusi eksperimen linking terhadap database produksi.
3. Ambil ZIP hasil GitHub Actions pada **commit yang sama** dengan Worker 10.49.0; pastikan root ZIP langsung berisi `index.html`, `_worker.js`, `my-sscircle.html`. Jangan upload ZIP source code GitHub ke Cloudflare.
4. Deploy ZIP Cloudflare Pages (Direct Upload / advanced mode Worker). Pastikan binding `DB`, `SESSION_SECRET`, `ADMIN_PASSWORD`, dan `SSCIRCLE_LINK_SERVER_SECRET` tetap tersedia di environment yang dituju; secret **jangan** dicantumkan dalam ZIP. Binding media yang sudah ada dipertahankan.
5. Verifikasi `https://DOMAIN/api/health` menampilkan release **10.49.0**. Buka Admin Control → Minecraft Sync; toggle/batas default 3.
6. **Jangan mengganti JAR Paper** hanya untuk fitur ini: versi **10.48.5** menggunakan protokol signed claim/stats yang kompatibel. Pertahankan `authme-mixed-mode.enabled`, endpoint, dan `server-secret.txt` yang berfungsi. Restart Paper hanya bila benar-benar melakukan perubahan plugin/config.
7. Login Profile sebagai member **Diterima** dengan password Dashboard. Klik Buat kode penghubung, masuk Minecraft sebagai akun tambahan, jalankan `/sscircle link SC-...`, kemudian konfirmasi nama dan edisi di Profile.
8. Jalankan `/sscircle status`, `/sscircle diagnose` (OP), `/sscircle sync` (OP), lalu periksa data akun/Season dan Admin Control → Minecraft Sync.
9. Uji hasil di staging sebelum mempublikasikan ke produksi.

Migrasi dapat ditinjau di `migrations/v10_49_0_multi_account.sql`. Worker membuat skema idempoten otomatis; workflow migrasi manual GitHub hanya untuk staging yang memang telah dikonfigurasi. **Jangan menjalankan migration SQL berulang dengan modifikasi manual**, dan jangan pernah reset D1.

## Rollback
Simpan ZIP rilis sebelumnya dan backup D1. Jika fitur baru mengganggu website, kembalikan Worker/Pages ke deployment sebelumnya yang kompatibel, dan periksa backup D1. Tabel baru bersifat aditif, **jangan DROP** tabel lama atau tabel baru untuk rollback. Plugin Paper 10.48.5 tidak perlu diubah.

## Batas uji
GitHub Actions menguji JS, kontrak worker, browser dan build plugin. CI **tidak** membuktikan alur Mojang/AuthMe/Floodgate pada hosting asli; wajib uji di server staging.

# SSCircle V10.48.4 — Keamanan identitas Minecraft

## Sasaran
Mencegah pengiriman link dan statistik dari sesi Java AuthMe yang berubah identitas
di tengah koneksi atau memiliki nama yang sama pada dua sesi secara bersamaan.
Mengungkap indikasi konflik kepada pengurus melalui Admin Control, **tanpa
memindahkan tautan akun atau UUID pemain secara otomatis**.

## Perubahan plugin Paper
- `IdentitySessionGuard` mencatat UUID koneksi Paper, nama login Java ternormalisasi,
  dan ID AuthMe lokal sejak `PlayerJoinEvent`; dihapus pada `PlayerQuitEvent`.
- Setelah AuthMe benar-benar mengautentikasi pemain, `/sscircle link` dan
  sinkronisasi statistik memerlukan bukti sesi yang **tetap sama**. Identitas yang
  berubah, belum terikat, atau dipakai oleh dua koneksi aktif ditolak. Pengaman
  bekerja di main thread, tanpa kueri database/HTTP pada tiap tick.
- Jika plugin diaktifkan saat pemain sudah online, sesi mereka dicatat saat
  `onEnable`. Semua catatan sesi dibersihkan saat plugin nonaktif.
- `/sscircle status` menampilkan peringatan yang dapat dipahami pemilik akun
  ketika sesi lokal tidak aman. Tidak mencetak secret, kode tautan, token, IP,
  ataupun data login mentah.

### Batas kemampuan
ID AuthMe lama diturunkan dari nama Java yang dinormalisasi. Jika nickname
benar-benar berubah atau database AuthMe dihapus/reset, **ID akun bisa berubah**.
Versi ini tidak mengklaim dapat membuktikan bahwa nama baru adalah pemilik akun
lama dan tidak mengganti ID otomatis. Pelaku yang memperoleh akses AuthMe sah
melalui kompromi password juga tetap membutuhkan mekanisme keamanan AuthMe.
Pemindahan akun harus dilakukan melalui pemulihan manual yang memeriksa
kepemilikan secara independen oleh pengurus.

## Perubahan web dan Cloudflare
- **Admin Control → Minecraft Sync** menerima kode warning aman untuk
  `NAMA_SAMA_PERIKSA`, `PREMIUM_BELUM_VERIFIKASI`, `BUKTI_LOGIN_LAMA`
  (lebih dari tujuh hari), dan `BUKTI_BEDROCK_BELUM_TERSEDIA`.
- Admin dapat melihat waktu bukti autentikasi terbaru. Angka statistik dan
  label edisi yang lama tidak dibuat-buat atau dipindah otomatis.
- Database menggunakan tabel `minecraft_accounts` dan
  `minecraft_identity_evidence` yang sudah ada. **Tidak ada migrasi D1,
  reset database, perubahan UUID, ataupun transfer akun otomatis.**
- Peringatan hanya tersedia melalui endpoint Admin yang memerlukan sesi admin.
  UI dibuat dari teks aman dan menyesuaikan tampilan HP.

## Pengujian wajib pada server staging
1. Backup `world/`, `world/playerdata/`, database AuthMe, D1 Cloudflare,
   dan `plugins/SSCirclePlayerSync/` (terutama `server-secret.txt` serta
   `stats-queue.properties`).
2. Jalankan Paper 26.3/Java 25 dengan AuthMe, PacketEvents, **satu** FastLogin
   atau FastLoginPlus serta dependensi ProtocolLib; Floodgate untuk Bedrock.
   Pastikan `authme-mixed-mode.enabled: true` hanya di mode campuran yang diuji.
3. Java Premium terverifikasi: login, `/sscircle status`, buat kode Profile,
   jalankan `/sscircle link <kode>`, konfirmasi di web. Pastikan data statistik
   masuk tanpa label Non-Premium palsu.
4. Java Non-Premium: autentikasi AuthMe, link dengan kode berbeda; periksa
   status FastLogin `CRACKED` atau `UNKNOWN`, dan pastikan identitas tidak
   diklaim sebagai Mojang Premium.
5. Bedrock melalui Floodgate: pastikan XUID dan link tetap bekerja walaupun
   nama Bedrock tidak memenuhi pola nama Java. Cek tab statistik dan Profile.
6. Coba dua koneksi yang mengklaim nama lokal sama, serta perubahan identity
   di tengah sesi. Harus ditolak; server tidak boleh memindahkan akun otomatis.
   Jangan menguji dengan mencuri akun milik pemain sungguhan.
7. Cabut FastLoginPlus di salinan staging dan restart. Akun Java lama tetap
   terhubung; status autentikasi baru bisa menjadi UNKNOWN, peringatan admin
   harus membantu diagnosis. Cek pembaruan setelah sinkronisasi yang berhasil.
8. Coba pergantian nickname atau UUID pada **salinan**: jangan auto-convert
   playerdata ataupun tautan. Gunakan prosedur recovery berikut.
9. Simulasikan kehilangan koneksi Cloudflare, reconnect, dan restart; cek
   `/sscircle diagnose`, `/sscircle sync`, Admin Sync, statistik, dan TPS.

## Prosedur account recovery
- Kunci sementara perubahan tautan saat identitas bertabrakan; periksa tiket
  secara privat, riwayat akun dan bukti kepemilikan yang independen.
- Backup dan periksa UUID, inventory, permissions, playerdata serta statistik
  sebelum memilih apa pun. Jangan gunakan username saja sebagai bukti.
- Jika harus memindahkan akun, lakukan dengan tindakan admin yang diaudit
  dan persetujuan pemilik, **bukan** perintah otomatis SSCircle.
- Uji hasil di staging sebelum diterapkan ke server utama. Jangan kirim file
  password, token Cloudflare, ataupun secret plugin di chat publik.

## Status verifikasi
Tes otomatis mengecek guard Java, konflik nama, peringatan read-only admin,
retensi akun lama, build Paper dan pengujian regresi website. CI tidak
menggantikan uji login Mojang/AuthMe/FastLoginPlus pada hosting nyata.
